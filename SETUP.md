# Настройка

Делай по порядку. Проще всего — через Claude Code со стартовым промптом
из [START_PROMPT.md](START_PROMPT.md): он проведёт по этим же шагам сам.

Сначала всё настраивается и проверяется в Telegram. WhatsApp и Instagram
подключаются в конце, по [CHANNELS.md](CHANNELS.md): мозг бота один на все
каналы, и проверять его проще там, где запуск занимает минуту.

---

## Шаг 0. Python

**Python 3.10 или новее.** Проверь в терминале:

```bash
python3 --version
```

Если команда не найдена — поставь Python с python.org.

---

## Шаг 1. Библиотеки

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`venv` — отдельная «песочница» для библиотек проекта. После `activate`
в начале строки появится `(venv)`. Активировать нужно в каждом новом терминале.

---

## Шаг 2. Файл .env

```bash
cp .env.example .env            # Windows: copy .env.example .env
```

Открываешь `.env` и заполняешь. Ниже — где брать значения.

---

## Шаг 3. BOT_TOKEN — сам бот

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot`
2. Имя (видно людям) и username (заканчивается на `bot`)
3. Скопируй токен вида `1234567890:AAH...` в `.env`:

```
BOT_TOKEN=1234567890:AAH...
```

> Токен = пароль от бота. Никому не показывай.

Совет: там же, в BotFather, команда `/setuserpic` — поставь боту аватарку,
а `/setdescription` — короткое описание. Клиенты доверяют боту с лицом.

---

## Шаг 4. ADMIN_ID — кто получает заявки

Telegram-бот — это ещё и панель менеджера: сюда приходят заявки из всех каналов,
включая WhatsApp и Instagram.


1. Напиши [@userinfobot](https://t.me/userinfobot), он пришлёт твой `Id`
2. Впиши:

```
ADMIN_ID=123456789
```

Несколько менеджеров — через запятую. Заявки придут всем.

**Важно:** каждый админ должен сам открыть бота и нажать «Старт»,
иначе бот не сможет ему написать.

## Шаг 5. Нейросеть

В `.env` достаточно одного слова в `LLM_PROVIDER` — адрес и модель шаблон
подставит сам. Сменить нейросеть потом = поменять это слово и ключ.

| `LLM_PROVIDER` | Что это | Где взять ключ |
|---|---|---|
| `deepseek` | самая дешёвая, по умолчанию | platform.deepseek.com → API Keys |
| `anthropic` | Claude Haiku: дороже, строже соблюдает правила | console.anthropic.com → API Keys |
| `gemini` | Google Gemini Flash-Lite | aistudio.google.com → Get API key |
| `openai` | OpenAI, модель указать в `LLM_MODEL` | platform.openai.com → API keys |
| `openrouter` | сотни моделей через один ключ, модель указать в `LLM_MODEL` | openrouter.ai → Keys |

Пример:

```
LLM_PROVIDER=deepseek
LLM_API_KEY=sk-...
```

В любом кабинете:

1. Пополни баланс — для старта хватит $5.
2. **Поставь лимит расходов**, если кабинет это позволяет.
3. Создай ключ и сразу скопируй: многие сервисы показывают его один раз.

**Сколько это стоит.** Для бота клиники с несколькими тысячами сообщений в месяц
счёт за нейросеть — от долей доллара (DeepSeek) до нескольких долларов (Claude Haiku).
Цены меняются, актуальные — на сайте провайдера. Это копейки по сравнению с ценой
одной ошибки бота, поэтому выбирай не только по цене, а по шагу 7.

**Где хранятся данные.** Переписка клиентов уходит на серверы выбранного провайдера.
DeepSeek — китайская компания. Если бизнес работает с чувствительными данными
(медицина, например), обсуди это с владельцем заранее.

## Шаг 6. База знаний

Здесь ассистент становится твоим. Нужно заполнить:

- `prompts/system.md` — кто ассистент: имя, роль, тон, чего нельзя
- `prompts/greeting.md` — приветствие
- файлы в `knowledge/` — услуги, цены, правила, частые вопросы

**Проще всего — через Claude Code**: он задаст вопросы по [INTERVIEW.md](INTERVIEW.md)
и сам всё запишет. Кинь ему сразу прайс, ссылку на сайт, частые вопросы клиентов —
так быстрее.

Руками тоже можно: образец формата — `knowledge/_example.md`.
Главное правило базы: **факты, коротко, без воды**. Чего не знаешь — не пиши,
бот сам позовёт менеджера.

## Шаг 7. Проверка и запуск

```bash
python check_setup.py
```

Проверяет токен, админов, ключ нейросети (один крошечный запрос) и базу знаний.
По каждой проблеме скажет, что чинить. Когда всё зелёное:

```bash
python bot.py
```

Тебе в Telegram придёт «✅ Бот запущен» со сводкой по базе знаний.
Остановить — `Ctrl+C`.

### Проверка ответов на реальных вопросах

```bash
python test_bot.py
```

Скрипт задаёт боту вопросы из `tests/questions.md` (их составляет Claude Code
под твой бизнес) и сам проверяет главное:

- ❌ если бот **выдумал** ответ, которого нет в базе
- ❌ если не оформил заявку, когда клиент оставил имя и телефон
- ❌ если не позвал менеджера, когда клиент недоволен
- 👀 остальное показывает тебе — проверь глазами

Результат сохраняется в `tests/results/`. **Чтобы сравнить нейросети:** запусти,
поменяй `LLM_PROVIDER` в `.env`, запусти ещё раз и сравни два файла. Бери
самую дешёвую из тех, что прошли проверку.

## Как проверить, что всё работает

Пиши боту сам, как клиент:

1. Обычный вопрос из базы — ответ точный и короткий
2. Вопрос, которого в базе нет — бот честно говорит и предлагает менеджера
3. «Хочу записаться, я Айгерим, 87001234567» — тебе приходит «📝 Новая заявка»
4. Кнопка «👤 Позвать человека» — тебе приходит карточка
5. Ответь на карточку через **Reply** (свайп влево по сообщению) — ответ приходит «клиенту», то есть тебе
6. Нажми «🤖 Вернуть клиента ИИ» — бот снова отвечает сам

Ответил неправильно? Поправь файл в `knowledge/`, напиши боту `/reload` — готово.

## Чтобы бот работал круглосуточно

На своём компьютере бот живёт, только пока компьютер включён. Для постоянной
работы нужен сервер — варианты (Railway или свой VPS) расписаны в
[CHANNELS.md](CHANNELS.md), раздел «Сервер». Для WhatsApp и Instagram сервер
обязателен.

## Дополнительные настройки

**Эффект «печатает, как человек».** Мгновенный ответ выдаёт робота. В `.env`:

```
REPLY_DELAY_SECONDS=6
```

Бот ответит не раньше чем через 6 секунд после вопроса, в Telegram всё это время
виден «печатает…». Если нейросеть сама думала дольше — лишнего ждать не будет.
Рекомендуем 5–8 для консультанта и поддержки. Больше 10 клиент начинает нервничать,
особенно в WhatsApp и Instagram, где индикатора «печатает» нет.

**Заявки в CRM или Google Таблицу.** Каждую новую заявку бот может отправлять
на адрес вебхука:

```
LEAD_WEBHOOK_URL=https://...
```

Адрес даёт n8n, Make или Zapier: создаёшь сценарий «Webhook → amoCRM / Bitrix24 /
Google Таблица», копируешь адрес вебхука сюда. Бот присылает JSON:

| Поле | Что внутри |
|---|---|
| `lead` | заявка целиком, как её записал ИИ — приходит всегда |
| `lead_name`, `lead_phone`, `lead_request`, `lead_time` | то же по полям. Телефон приводится к виду `+77011234567` / `+998901234567`, только если формат опознан наверняка; иначе — ровно как написал клиент |
| `lead_parsed_ok` | `false`, если ИИ оформил заявку не по формату или без имени/телефона |
| `channel`, `name`, `username`, `created_at` | откуда клиент и когда |

**Совет для CRM:** всегда сохраняй `lead` в примечание к сделке, а по
`lead_parsed_ok = false` ставь задачу «проверить заявку». Нейросеть иногда
оформляет заявку не так, как просили. Бот в таком случае не гадает: поля
остаются пустыми или с данными из профиля, а целиком текст есть в `lead`.
Проверить можно на webhook.site: вставь его адрес, оставь боту заявку и посмотри,
что пришло. Если CRM не отвечает, диалог с клиентом не страдает: ошибка уйдёт в лог,
а заявка всё равно сохранится в боте и придёт тебе в Telegram.

**Страховка от потерянных заявок.** Если клиент написал номер телефона, а ИИ
не оформил заявку и не позвал менеджера, через 10 минут тебе придёт карточка
«⚠️ Возможно, пропущена заявка». Ничего настраивать не нужно. Если такие карточки
приходят часто — нейросеть плохо соблюдает правила: прогони `test_bot.py` и
подумай о более сильной модели.

## WhatsApp и Instagram

Когда бот хорошо отвечает в Telegram — подключай остальные каналы по
[CHANNELS.md](CHANNELS.md). Коротко: сервер с https-адресом → аккаунт Meta →
канал → вебхук → проверка с личного аккаунта. В `.env` строка:

```
CHANNELS=telegram,whatsapp,instagram
```

## Что делать, если сломалось

| Что видишь | В чём дело |
|---|---|
| `ConfigError: ...` | в `.env` что-то не заполнено или не того формата — текст ошибки скажет что |
| `Unauthorized` при запуске | неверный `BOT_TOKEN` |
| «ключ LLM_API_KEY не подходит» | ключ скопирован не целиком или удалён |
| «закончились деньги» | пополни баланс у провайдера нейросети |
| Заявки не приходят | админ не нажал «Старт» у бота |
| Бот отвечает не то | поправь базу знаний в `knowledge/` и напиши боту `/reload` |
| Бот выдумывает | в `knowledge/` нет этой информации — добавь или напиши «уточнить у менеджера» |
| WhatsApp или Instagram молчат | таблица «Если не работает» в CHANNELS.md |

Первым делом всегда: `python check_setup.py`.
