# Контекст проекта для Claude Code

## Что это

Универсальный ИИ-ассистент: консультант бизнеса, куратор курса или поддержка.
Роль задаётся содержимым `prompts/` и `knowledge/`, код один.
Каналы для клиентов: Telegram, WhatsApp (Cloud API), Instagram (API with
Instagram Login) — включаются строкой `CHANNELS` в `.env`.
Telegram-бот работает всегда: это ещё и панель менеджера для всех каналов.

Python + aiogram 3 (long polling) + aiohttp (веб-сервер для вебхуков Meta), SQLite.
Нейросеть: `LLM_PROVIDER` = deepseek (по умолчанию) | anthropic | gemini | openai | openrouter.
Пресеты в `config.PROVIDERS`: формат API, адрес, модель по умолчанию.

## Кто пользователь

Владелец бота — как правило не программист. При общении с ним:
объяснять простыми словами, давать конкретные шаги, спрашивать по одному
значению за раз, самому вносить правки в файлы. Кабинеты Meta меняются —
если экран не совпадает с CHANNELS.md, просить скриншот.

## Устройство

```
bot.py                 запуск: Telegram polling + веб-сервер (если есть WhatsApp/Instagram)
core.py                общая логика: Client, handle_text, заявки, передача менеджеру,
                       окно 24 ч, карточки админам, отчёт о сбоях
tg.py                  Telegram: клиентский канал + панель менеджера (команды, Reply, кнопки)
channels/meta.py       общее для Meta: проверка вебхука, подпись X-Hub-Signature-256, Graph API
channels/greenapi.py   WhatsApp по QR (WHATSAPP_VIA=greenapi): опрос очереди receiveNotification,
                       отправка, пауза при ответе с телефона, страница /connect/<secret>
channels/whatsapp.py   официальный WhatsApp (WHATSAPP_VIA=meta): /webhook/whatsapp, медиа, статусы
channels/instagram.py  приём /webhook/instagram, отправка (≤1000 байт), автопродление токена
knowledge.py           системный промпт: prompts/system.md + SERVICE_RULES + knowledge/*
llm.py                 один вход ask(system, history), форматы anthropic / openai-совместимый;
                       llm.LAST_USAGE — расход токенов последнего ответа
test_bot.py            прогон tests/questions.md без Telegram: автопроверки + отчёт в tests/results/
db.py                  SQLite: users, messages, leads, relay, kv — ключ клиента «канал:id»
config.py              чтение .env + валидация, ConfigError с человеческим текстом
check_setup.py         диагностика всех частей + значения для вебхуков Meta
CHANNELS.md            пошаговая инструкция: сервер, Meta, WhatsApp, Instagram
INTERVIEW.md           сценарий сбора базы знаний у владельца
```

## Ключевые механизмы

- **Клиент** — `core.Client(channel, id)`, ключ `tg:<chat_id>`, `wa:<номер>`, `ig:<IGSID>`.
  Каналы только принимают сообщения и регистрируют отправку в `core.SENDERS`.
- **Метки ИИ** `[[ЗАЯВКА]]` и `[[ОПЕРАТОР]]` — контракт между `knowledge.SERVICE_RULES`
  и `core.parse_reply`. Меняешь одно — меняй и другое.
- **Формат заявки** — с подписями: `имя: …; телефон: …; что нужно: …; время: …`.
  `core.parse_lead_fields` разбирает по подписям (порядок не важен), а без подписей
  верит только строгому «имя; телефон; …». Всё остальное — `lead_parsed_ok=False`,
  текст целиком в `lead_request`. Не добавлять «угадывание» имени: отличить имя от
  услуги по тексту нельзя, а мусор в CRM хуже пустого поля. Менеджер при
  `lead_parsed_ok=False` получает в карточке переписку, `test_bot.py` ставит ❌.
- **Телефоны** (`core.normalize_phone`): единый вид `+…` только для опознанных форматов —
  явный `+`, KZ/RU (8/7, 11 цифр; 10 цифр на 7), коды СНГ без `+`. Всё остальное
  (местные номера Беларуси «8 0…», Кыргызстана «0…», Узбекистана) — как написал клиент.
  Не форсить +7: бот работает по всему СНГ, испорченный номер хуже некрасивого.
- **Менеджер** отвечает Reply на карточку в Telegram. Таблица `relay` связывает
  карточку с ключом клиента. Ответ уходит в канал клиента (WA/IG — только текст).
- **Окно 24 часа** — только для каналов в `core.WINDOW_CHANNELS` (Instagram и WhatsApp
  через Meta). У WhatsApp через Green API окна нет: это обычный аккаунт.
- **Green API** не использует вебхуки: `greenapi.poll_loop` забирает уведомления,
  сразу подтверждает (deleteNotification) и обрабатывает в фоне. Типы:
  `incomingMessageReceived` — клиент; `outgoingMessageReceived` — ответ с телефона →
  режим `human` (если `WHATSAPP_PAUSE_ON_PHONE_REPLY`); `outgoingAPIMessageReceived` —
  наш же ответ, игнорируется; `stateInstanceChanged` — номер отвязался → алерт админам.
  Группы (`@g.us`) игнорируются. Ссылка `/connect/<CONNECT_SECRET>` даёт привязать
  номер к боту — не логировать и не показывать её никому, кроме админов.
- **Не добавлять функции рассылки или первого сообщения** для WhatsApp через Green API:
  это главный повод для блокировки номера.
- **Вебхуки** отвечают Meta сразу (`EVENT_RECEIVED`), а обработка идёт в фоне.
  Повторная доставка отсекается `core.seen(message_id)`.
- **Пауза перед ответом** `REPLY_DELAY_SECONDS`: в `handle_text` досыпаем остаток после
  ответа нейросети. Только для обычного ответа ИИ — системные сообщения уходят сразу.
- **Выгрузка заявок** `export_lead` → `LEAD_WEBHOOK_URL`, фоновой задачей через
  `run_in_background`, ошибки только в лог. `test_bot.py` зовёт `llm.ask` напрямую и
  вебхук не трогает — тестовые вопросы в реальную CRM не попадают. Так и оставить.
- **Страховка заявок**: телефон в сообщении (`has_phone`) без `[[ЗАЯВКА]]` и
  `[[ОПЕРАТОР]]` → строка в лог и `check_missed_lead`: через 10 минут карточка
  менеджеру, если заявка так и не появилась и клиент не у менеджера.
- **Токен Instagram** живёт 60 дней: `instagram.refresh_loop` продлевает раз
  в неделю и хранит свежий в `kv`. Новый токен в `.env` автоматически заменяет сохранённый.

## Правила при доработках

- **База знаний — это файлы, не код.** Правки фактов, цен, тона — только в
  `prompts/` и `knowledge/`. После правки владелец пишет боту `/reload`
  (на сервере сначала задеплоить изменения).
- **Ничего не придумывать в базе.** Если факта нет — «уточнить у менеджера».
- **Секреты только через .env.** Новое значение — в `config.py` и в `.env.example`
  с комментарием. На сервере (Railway) настройки живут в Variables, а не в `.env`.
- **Клиент никогда не остаётся без ответа.** Сбой нейросети → извинение и передача
  менеджеру. Сбой обработки WA/IG → `core.safe_handle` извиняется и шлёт отчёт.
  Errors-хэндлер в `tg.py` не ломать.
- **Подпись вебхуков не отключать.** Без неё кто угодно может слать боту
  «сообщения клиентов» и тратить бюджет нейросети.
- **Ответы ИИ отправляются без разметки** (`parse_mode=None` в Telegram).
  Служебные сообщения админам — HTML, всё пользовательское через `core.esc()`.
- **Внешние сервисы не должны ломать диалог.** Выгрузку в таблицу/CRM делать
  фоновой задачей, которая глотает свои ошибки и пишет только в лог.
- **Новый канал** = модуль в `channels/`: приём → `core.handle_text` / `core.handle_media`
  внутри `core.safe_handle`, отправка → регистрация в `core.SENDERS`, плюс
  ветка в `config.py`, `bot.start_webserver`, `check_setup.py`, `CHANNELS.md`.
- **Большая база** (>60 000 символов) — делать поиск по фрагментам, а не раздувать промпт.
- **Новый провайдер** с OpenAI-совместимым API — одна строка в `config.PROVIDERS`
  и строчка в таблице SETUP.md (шаг 5) и `.env.example`. Названия моделей у провайдеров
  меняются — модель по умолчанию проверять по их документации, не по памяти.
- **Параметры модели.** Некоторые модели не принимают `max_tokens` / `temperature` —
  если провайдер ругается на параметр, поправь `_openai` в `llm.py`.
- **После любой правки базы знаний или смены модели** — `python test_bot.py`.
  Формат `tests/questions.md` описан в самом файле; значки - ? ! @ ~ задают ожидание.
- **Тексты для клиентов — на русском**, на «ты», если владелец не выбрал «вы»
  (тогда поправь и служебные тексты в `core.py` и `tg.py`).
- Ничего не коммитить в git без явной просьбы. `.env` и `*.db` в `.gitignore`.

## Проверка после изменений

```bash
python check_setup.py     # настройки, база знаний, каналы
python test_bot.py        # ответы на вопросы из tests/questions.md
python bot.py             # бот стартует, админу приходит «Бот запущен» со статусом каналов
```

Отдельно проверить затронутый сценарий: вопрос из базы, вопрос вне базы,
заявка, «менеджер» → Reply админа → «Вернуть клиента ИИ» — в каждом включённом канале.
